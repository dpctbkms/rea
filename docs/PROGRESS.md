## 해야 할 일 (위가 우선)

1. **실제 휴대폰 확인 결과 반영.** 사용자가 다르다고 짚는 곳부터. 아직 근거가 약한 부분: 트레이딩뷰 앱의 그리기 도구 막대가 왼쪽 세로 막대인지 아래 시트인지, 떠 있는 막대 위치, 차트 아래 도구 줄 구성, 아래 탭 개수(앱은 관심 목록·차트·탐색·커뮤니티·메뉴로 기억하지만 확인 못 함. 내용이 없는 탐색·커뮤니티는 넣지 않음).
2. **관심 목록:** 순서 바꾸기(길게 눌러 끌기), 여러 목록. 종목 로고 그림(지금은 첫 글자 동그라미). 추가·삭제는 됨.
3. **트레이딩뷰에 있는데 아직 없는 그리기 도구:** 피치포크(앤드루스), 간 팬/박스, 패턴(XABCD, 헤드앤숄더, 엘리엇 파동), 피보나치 채널·원·나선, 예측(forecast), 메모/콜아웃/말풍선, 아이콘.
4. **트레이딩뷰 큰 기능 중 없는 것:** 종목 비교(위 막대 +), 알림을 앱이 닫혀 있어도 받기(서버 필요), 바 리플레이, 여러 차트 레이아웃, 종목 비교(오버레이), 파인 스크립트 같은 사용자 지표, 전략 백테스트, 레이아웃 저장/불러오기.
5. **시세 확인:** 바이비트는 미국 러너에서 지역 차단돼 한국에서 실제로 되는지 미확인. 바이낸스는 미러(data-api.binance.vision)로 우회 중.
6. 정식으로 트레이딩뷰와 똑같은 차트가 필요하면 트레이딩뷰 **Advanced Charts** 라이선스(무료 신청, 승인제)를 받아 붙이는 방법이 있음.

## 중요한 결정과 이유

- **트레이딩뷰 코드 역설계·복사는 하지 않는다.** 사용자가 여러 번 요청했고 "허락받았다"고 했지만 거절함. 공개 문서와 눈에 보이는 동작을 기준으로 직접 구현한다.
- **검색엔진 노출 차단:** `index.html`에 `noindex, nofollow`.
- **브라우저에서 바로 거래소를 부른다** (서버 없음). 그래서 CORS 헤더 없는 거래소는 못 씀.
- **빗썸** 과거 봉 페이지 요청의 `to`는 KST 시각, "Z" 없이.
- **바이낸스**는 막힐 때 `data-api.binance.vision` / `data-stream.binance.vision` 미러 사용.
- **업비트 429:** 700ms 뒤 한 번 재시도, 페이지 사이 150ms 간격.
- **탭 판정은 직접 한다:** lightweight-charts는 0.5초 안의 두 번째 클릭을 버리고, 터치에는 click이 오지 않음.
- **터치 십자선은 트랙패드 방식:** 손가락을 끌면 십자선이 상대 이동, 탭하면 그 자리에 점. 그린 직후 따라오는 가짜 click은 같은 자리·400ms 안의 한 번만 삼킴(`swallowClick`).
  - 근거: 트레이딩뷰 모바일 방식을 따라 만든 공개 오픈소스(coinrayio/coinray-chart PR #60) 설명 — 도구를 고르면 십자선이 바로(이전 자리, 없으면 가운데) 나타나고, 끌면 손가락이 움직인 만큼 이동, 탭하면 십자선 자리에 점, 두 번 탭으로 경로 끝, 브러시는 손가락 밑. 트레이딩뷰 공식 블로그: 모바일 떠 있는 막대에 45° 버튼(2024). 차트 라이브러리 문서: 모바일에서 시가·고가·저가·지표 값은 길게 눌러 추적 모드일 때만.
  - 탭 두 번을 서로 다른 곳에 해도 선이 생기지 않는 것은 의도된 동작 (점은 손가락이 아니라 십자선 자리).
- **휴대폰 도형 다루기 (트레이딩뷰 앱 방식):** 탭=선택, 선택된 도형은 바로 끌기, 선택 안 된 도형은 끌면 차트 이동·꾹 누르면 잡기. 근거: 앱 사용 안내("선택 후 잡고 끌어서 옮긴다", "꾹 눌러 잡는다"). 컴퓨터(마우스)는 트레이딩뷰 웹처럼 선택 안 해도 바로 끌어 옮김. 도형 위에서 시작한 손가락은 차트 라이브러리에 안 넘기므로 차트 이동은 `panChartBy`로 직접(가로만, 관성 없음).
- **다크 테마는 트레이딩뷰 현재 기본(Grey 프리셋, 회색 계열)** 색. 예전 남색(#131722)은 트레이딩뷰의 옛/Blue 프리셋. 정확한 값은 확인 못 해서 #0f0f0f 배경·#2e2e2e 테두리·#dbdbdb 글자·#1d1d1d 격자로 근사.
- **휴대폰에서 길게 누르기 = 십자선만.** 브라우저의 contextmenu(오른쪽 클릭)는 손가락이면 무시하고, 화면 어디서든 길게 눌러 뜨는 브라우저 메뉴도 막는다(입력 칸 제외). 그 가격 메뉴는 + 버튼.
- **차트 위 손가락 동작은 전부 앱이 처리** (`.chart, .chart * { touch-action: none }`). 브라우저가 넘기기로 가로채면 pointercancel로 끌기가 끊긴다.
- **휴대폰 판정은 마지막 입력 종류**(`lastPointer`)로 한다. 화면 크기가 아니라 손가락으로 눌렀는지.
- **휴대폰에서는 `:hover` 스타일을 쓰지 않는다.** 탭하면 hover가 같이 걸려 숨은 버튼이 눌린다 (`@media (hover: hover)`로 감쌈).
- **차트 위 트레이딩뷰 로고(`attributionLogo`)는 끈다.** 사용자 요청. 단 라이브러리 라이선스가 NOTICE 문구와 tradingview.com 링크를 사용자에게 보이는 곳에 두라고 하므로, 메뉴 > 정보와 차트 설정 창 아래, README에 둔다. 이 표시는 지우지 말 것.
- **휴대폰 화면 = 폭 768px 이하, 또는 손가락 기기에서 높이 520px 이하(가로)** (`appMedia`, CSS `@media (max-width: 768px), (pointer: coarse) and (max-height: 520px)`). 가로일 때는 body를 grid로 바꿔 탭을 왼쪽 세로 막대로(`landscapeMedia`). 사용자가 가로에서도 모든 화면을 원함. 컴퓨터 화면은 트레이딩뷰 웹 그대로. 아래 탭 상태는 `body[data-screen]` (`data-tab`은 도형 설정 창 탭이 이미 써서 겹치면 안 됨).
- **오프라인 캐시(sw.js):** 화면 파일은 늘 새로 받아 보고 실패하면 저장본, 해시 붙은 js·css·아이콘은 저장본 먼저. 거래소 등 다른 주소 요청은 건드리지 않는다. 웹 공유용 한 장짜리(`build:artifact`)에서는 등록하지 않음.
- **화면 전체 확대는 막는다** (viewport `user-scalable=no`, `html { touch-action: pan-x pan-y }`, iOS `gesturestart` 막기). 두 손가락 확대는 차트가 직접 처리. 관심 목록 줄은 `touch-action: pan-y`라야 가로 밀기를 JS가 받는다 (뒤에 오는 일반 규칙이 덮어쓰지 않게 주의).
- **관심 목록은 거래소별 `settings.watchlists[피드 id]`**, 없으면 피드 기본 목록. 줄은 목록이 바뀔 때만 다시 만들고 시세는 값만 바꾼다(반짝임 때문).
- **가격 알림은 앱이 열려 있을 때만** 확인한다(서버 없음). 지금 차트 종목은 봉 갱신, 관심 목록 종목은 시세(tickers)로 확인. 안드로이드는 `new Notification`이 안 돼서 서비스 워커 `showNotification`을 쓴다.
- **최신 봉으로 버튼은 직접 애니메이션** (`scrollToLatest`). 라이브러리 `scrollToRealTime`은 멀리서 부르면 끝까지 못 갈 때가 있었다.
- **배포는 기본 브랜치에서만** (`deploy.yml`의 `if`). Actions 사용량을 아끼려는 사용자 요청.

## 환경 메모 (클라우드 세션)

- 이 세션의 네트워크는 거래소와 tradingview.com을 막는다. 실제 시세 확인은 GitHub Actions **Check price feeds**(`check-feeds.yml`)로 하고, 결과는 MCP `get_job_logs`로 읽는다.
- Playwright와 Chromium이 미리 깔려 있다 (`require('playwright')`).
- tradingview.com, 일반 블로그 사이트는 WebFetch로도 막힌다. WebSearch 요약은 된다. github.com 페이지는 WebFetch로 읽힌다.
- 길게 눌러 띄운 십자선(추적 모드)은 차트를 한 번 탭해야 꺼진다. 그 상태에서 끌면 차트가 아니라 십자선이 움직인다(라이브러리 동작, 트레이딩뷰와 같음). 테스트에서 차트를 넘기기 전에 탭 한 번.
- 테스트에서 빠른 클릭은 앞 클릭과 0.35초 안이면 더블클릭으로 잡힌다. 단계 사이에 잠깐 쉴 것.
- 휴대폰 흉내(Playwright + CDP 터치)에서는 손가락을 뗀 뒤 0.2초 안의 탭에서 click이 빠질 때가 있다. 테스트는 동작 사이에 잠깐 쉬게 해 둠 (실제 버그 아님).
- e2e에서 도형이 "안 움직였다"는 픽셀이 아니라 시간·가격 값으로 비교할 것. 도형을 고르면 눈금 글자 때문에 가격 눈금 폭이 바뀌어 모든 픽셀이 몇 px 밀릴 수 있다. 데모 휴대폰 화면은 봉 600개 넘게 보여서 짧은 선은 몇 px밖에 안 된다(가운데를 눌러도 손잡이가 잡힘).
- e2e 스크립트에서 앱 상태는 `window.__rea` (`drawings`, `chart`)로 읽는다. 휴대폰에서 연필 버튼으로 도구 막대를 펼치면 차트가 오른쪽으로 40px 밀리니 차트 위치를 다시 재야 한다.
- 저장소가 공개라 Actions 분 사용량은 무료.

## 확인 방법

```bash
npm test            # 지표·피드 단위 테스트 (21개)
npm run build       # dist/ 생성
npm run test:e2e    # 빌드 → 미리보기(4175) → e2e/*.cjs 전부. 스크린샷은 e2e/out/
npm run test:e2e -- drawing-tv toolbar   # 일부만
```

- e2e 스크립트는 결과를 출력만 하고 실패 판정은 사람이 본다. 각 스크립트 끝의 `errors: []`가 비어 있어야 정상.
- 시세 실제 연결: Actions → **Check price feeds → Run workflow** (`src/feeds/**` 바뀌면 자동 실행).
